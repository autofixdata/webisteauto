# Deploy ZIP for CyberPanel (Ubuntu)

## Quick: create upload ZIP on your Mac

```bash
cd /path/to/autofixdata-platform
npm run pack:deploy
```

This creates **`deploy/autofixdata-deploy.zip`** (~6–8 MB) inside the project folder.

Upload that ZIP to your server (SFTP or CyberPanel File Manager), unzip, then:

```bash
cd autofixdata-deploy
npm ci
npm run build
pm2 start npm --name autofixdata -- start
```

Configure CyberPanel reverse proxy to `http://127.0.0.1:3000`.

## What is excluded from the ZIP (do not upload these)

| Exclude | Why |
|--------|-----|
| `node_modules/` | Install on server with `npm ci` (~400 MB) |
| `.next/` | Built on server with `npm run build` (~2 GB) |
| `.git/` | Not needed on server |
| `.github/` | CI only |
| `tools/` | Local dev scripts (dictionary generators, etc.) |
| `scripts/lighthouse-audit.mjs` | Dev audit only |
| `scripts/generate-dtc-db.js` | Regenerates JSON; data already in `src/lib/` |
| `public/sitemap*.xml` | Regenerated by `npm run build` → `postbuild` |
| `.DS_Store`, `.env*`, logs | Junk / secrets |

## Change domain (SEO)

Edit **`site.config.js`** at the project root:

```javascript
SITE_URL: 'https://www.autofixdata.net',
```

Then run `npm run build` and redeploy. Sitemap, robots.txt, and canonical URLs update automatically.

## ISR Cache Management & Disk Space Optimization

To prevent disk saturation from Next.js's default unlimited ISR caching (which can grow to tens of gigabytes from crawler activity on dynamic vehicle combinations), we have implemented a size-limited cache system.

### 1. How it works
- **Filesystem LRU (Default)**: Dynamic page metadata/tags are cached in `.next/cache/custom-isr-cache/`. If the cache folder exceeds `ISR_CACHE_LIMIT_MB` (default `2048 MB`), the least recently accessed files are evicted automatically.
- **Redis (Optional)**: If `@neshca/cache-handler` is installed and a Redis environment variable is present, caching will automatically use Redis (which handles its own LRU eviction based on your Redis configuration).

### 2. Configuration (Environment Variables)
Add these to your environment or `.env` files if you want to customize:
- `ISR_CACHE_LIMIT_MB`: The max disk space (in MB) allowed for the filesystem cache. (Default: `2048`)
- `ISR_CACHE_DIR`: Override the default cache folder location.
- `REDIS_URL`: Connects to Redis (e.g. `redis://localhost:6379`) to activate Redis caching.

### 3. Weekly Cron Job (Cleanup of rendered pages)
Next.js also writes compiled page HTML/RSC payloads directly to the server folder (`.next/server/app`). These are not governed by the cache handler.
To safely purge these files without losing the pre-rendered pages built during `npm run build`, set up a weekly cron job to run the cleanup script.

```bash
# Edit crontab
crontab -e

# Add weekly job (every Sunday at 3:00 AM)
0 3 * * 0 /home/YOUR_USER/autofixdata-deploy/scripts/clean-isr-cache.sh > /home/YOUR_USER/clean-isr-cache.log 2>&1
```

You can run it manually on the server to check:
```bash
bash scripts/clean-isr-cache.sh
# Or test what will be deleted without actually deleting:
bash scripts/clean-isr-cache.sh --dry-run
```

## SEO verification after hreflang / sitemap fixes

After deploying SEO changes:

1. **Ahrefs Site Audit** — Start a new crawl (or wait ~48h). Confirm **Localization** errors drop and **4XX in sitemap** is 0.
2. **Google Search Console** (28 days) — Watch **Pages** indexed count, **International targeting** → hreflang, and **Not found (404)** coverage.
3. **Spot-check** one URL (e.g. `/en/pricing`) — View source: one hreflang set per locale + `x-default`, no duplicate homepage alternates.
4. **Rich Results Test** — Sample product, blog, and DTC URLs if structured-data notices persist.

Success: health score up, localization errors near zero, no new 404s on money pages (pricing, products, top DTC).
